# Phase 14.2 — Sahayak Dataset Contract & Diversity Correction

## 1. Source of Truth & Canonical Contract Mapping
An explicit review of the Kotlin source files (`SahayakAIRequest.kt`, `SahayakAIResponse.kt`, `SahayakAIRecommendation.kt`, `SahayakAISecurityContext.kt`, `Evidence.kt`) revealed severe drift in the initial v0.1 dataset. 
- The field `recommended_next_step` does **not** exist natively in `SahayakAIResponse`. The Android canonical contract uses an optional `SahayakAIRecommendation` nested object containing `safeNextStep`, `requestedCapability`, and `capabilityReason`.
- `trust_level` is explicitly managed inside `SecurityAnalysisCoordinator` during `logAudit()` to track *provenance*; it is strictly **omitted** from `SahayakAIRequest` and `SahayakAISecurityContext`.

The Python dataset schema at `Sahayak-AI/dataset/schema/sahayak_schema.py` was completely refactored to perfectly mirror this canonical contract, ensuring OS authorization flows remain completely independent of AI-generated advice.

## 2. Dataset Correction & Re-Generation
The generator was rebuilt into `deterministic_generator_v2.py` as a compositional grammar combining intents, content types, security signals, and languages.

### Diversity Dimensions:
- **Languages:** English, Hindi, Marathi, En-Hi Code-Mixed.
- **Scenarios:** Meeting confirmations, delivery notices, conversational snippets (Benign); urgent phishing URLs (Suspicious); explicit demands for `EXECUTE_CODE` and `MAKE_PAYMENT` (Refusal); context-less ambiguous sentences (Uncertainty).
- **User Intents:** The scenarios were permuted across multiple user task requests (`ASSESS_SECURITY`, `SUGGEST_SAFE_NEXT_STEP`, `EXPLAIN_CONTENT`).

### Resolution of Structural Concerns:
- **Trust Isolation:** The model is no longer fed `trust_level`, permanently preventing the model from hallucinating a correlation between its assessment and a privileged OS trust state. 
- **Capability Refusals:** When a user payload requests a dangerous capability, the model explicitly populates `requestedCapability = null` (in the recommendation object), blocking any notion of autonomous execution.
- **Evidence Grounding:** 100% of generated evidence references strictly correspond to substrings natively extracted from the untrusted payload.

## 3. Dataset Size & Structural Splits
**Total Examples:** 1,146
- Train: 802
- Validation: 171
- Test: 173

Splits were generated by category block randomization. While compositional permutations were utilized to scale up (e.g. cross-multiplying user intent parameters with content variations), we capped the dataset growth deliberately to avoid superficial over-training.

## 5. Remaining Limitations
Because the dataset is fully deterministic, the linguistic diversity remains limited strictly to the predefined grammar branches. The dataset achieves robust semantic compliance and perfectly teaches the boundary definitions, but real-world fine-tuning may still require LLM-augmented syntactic paraphrasing (with rigorous output validation gates) to prevent overfitting on the templated markers.
