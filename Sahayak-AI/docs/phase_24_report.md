# Phase 24 — RTX 5050 SM_120 Supported Runtime Discovery

## A. Hardware
- **GPU:** NVIDIA GeForce RTX 5050 Laptop GPU
- **Compute Capability:** 12.0 (sm_120)
- **VRAM:** 7.96 GB Usable

## B. Previous Phase 23 Failure
In Phase 23, PyTorch wheels built with `cu124` up to version `2.6.0` catastrophically failed on `sm_120`. They raised `no kernel image is available for execution on the device` during any fundamental CUDA operation because the `cu124` distribution lacks the necessary SASS binaries or compatible PTX.

## C. Candidate Runtimes Investigated
The Python package indexes were searched across nightly and stable wheels for versions exceeding `cu124`.
- **Nightly `cu128`:** Not found on PyTorch Windows index.
- **Nightly `cu126`:** Not found on PyTorch Windows index.
- **Stable `cu128`:** Available up to `2.11.0+cu128`.

## D. Compatibility Evidence
NVIDIA's CUDA 12.8 Toolkit introduces official `sm_120` architecture support. Thus, a PyTorch wheel built specifically against `cu128` contains the required compiled `sm_120` binaries, resolving the missing kernel image error.

## E. Candidate Runtime Selected
An isolated candidate environment was built: `Sahayak-AI/gpu_venv_sm120`.
- **PyTorch Version:** `2.11.0+cu128`
- **Installation Source:** `https://download.pytorch.org/whl/cu128`
- **Transformers Version:** `5.17.0` (required to decode Qwen's SAFETENSORS tokenizer)

## F. CUDA Fundamental Test Results
Fundamental `torch.randn`, tensor addition, matrix multiplication, sum reductions, and small `torch.nn.Linear` layers executed natively on CUDA.
- **Result:** `CUDA_RUNTIME_STATUS = VERIFIED`

## G. Architecture/Kernel Evidence
PyTorch `2.11.0+cu128` reported the following natively supported compiled architectures:
`Arch list: ['sm_75', 'sm_80', 'sm_86', 'sm_90', 'sm_100', 'sm_120']`
The inclusion of `sm_120` conclusively proves this runtime is appropriate for the RTX 5050.

## H. Qwen Result
The local, verified `Qwen/Qwen3-4B` model was successfully loaded using `device_map="auto"` and `torch.bfloat16`.
- **Forward Pass:** SUCCESS

## I. Generation Result
The zero-generation guard was successfully overcome. The model successfully received the prompt and generated 30 valid tokens, successfully returning the exact generated bytes without crashing on charmap boundaries.
- **Generation:** SUCCESS

## J. Exact Failures
- The `cu128` package is ~2.6 GB and heavily rate-limited or sluggish from the official index. `uv` timed out downloading it iteratively. It had to be explicitly installed using `pip` with a 600s timeout over a long period.
- Attempting to load the Qwen tokenizer with `transformers==4.44.2` caused an untagged enum `ModelWrapper` parser error. This was immediately resolved by upgrading to `transformers==5.17.0` matching Phase 19 state.
- Attempting to print `\u20b9` (Rupee symbol) in Windows default CMD caused a `charmap codec` crash at generation-time; the Python script was patched to safely encode the output to UTF-8 before printing.

## K. Reproducibility Commands
```powershell
uv venv Sahayak-AI\gpu_venv_sm120 --python 3.12.10 --seed
Sahayak-AI\gpu_venv_sm120\Scripts\activate.ps1
python -m pip install torch==2.11.0+cu128 torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128 --timeout 600
python -m pip install transformers==5.17.0 accelerate
```

## L. Recommendation for the Next Phase
The environment `gpu_venv_sm120` has unequivocally solved the `sm_120` PyTorch compatibility issue and successfully generated tokens locally. The Sahayak AI environment baseline should be updated to point to this `cu128` distribution.
